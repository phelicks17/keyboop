# Подсказка продолжения текста (inline prediction)

Статус: проект, опциональная функция, по умолчанию ВЫКЛЮЧЕНА. Чистая реализация по наблюдаемому
поведению Cotypist: ни кода, ни ресурсов, ни файлов моделей Cotypist здесь нет.

## Что делает

Пока человек печатает в любом поле, Keyboop после короткой паузы предлагает продолжение фразы
серым «призрачным» текстом рядом с кареткой. Tab (настраивается) вставляет подсказку, любая
другая клавиша её убирает и уходит в приложение как обычно. Всё считается на этом Mac, в сеть
уходит только однократное скачивание модели по кнопке.

## Модель

| Что | Значение |
| --- | --- |
| Модель | Gemma 4 E2B instruct, GGUF, квантование Q4_K_M |
| Репозиторий | `unsloth/gemma-4-E2B-it-GGUF` |
| Ревизия (неизменяемая) | `0314792d7f1f7e229411f620751375812bb9faf2` |
| Файл | `gemma-4-E2B-it-Q4_K_M.gguf`, 3 106 738 272 байт |
| SHA-256 | `740185b21d22ceb83a11c3aa62ad5842ef32c70f6096d756bbee85a1e4ec34b8` |
| Лицензия | Apache-2.0 (карточка `google/gemma-4-E2B-it`) |

Почему этот репозиторий. `ggml-org/gemma-4-E2B-it-GGUF` (сопровождающие llama.cpp) отдаёт только
Q4_0, а базовая модель `ggml-org/gemma-4-E2B-GGUF` только BF16 и Q8_0. У bartowski Q4_K_M весит
3,46 ГБ. Unsloth даёт Q4_K_M в 3,1 ГБ. Хеш взят из LFS-метаданных HF (`paths-info` на пиннутой
ревизии) и совпадает с `X-Linked-ETag`, первые байты файла проверены (`GGUF`, версия 3).

Скачивание повторяет `ModelDownloader`: только по кнопке, URL с commit-ревизией, потоковый SHA-256
после загрузки (тем же `ModelDownloader.sha256`), несовпадение = файл удаляется. Зеркала на
keyboop.com для этой модели пока нет: если оно появится, достаточно добавить его первым источником.

## Движок: llama.cpp и конфликт с ggml из whisper.cpp

whisper.cpp уже статически влинкован в бинарь вместе со своей копией ggml (`-lggml -lggml-base
-lggml-cpu -lggml-metal`). llama.cpp несёт свою копию ggml, и версии почти никогда не совпадают:
Gemma 4 требует свежий ggml, а ggml внутри vendored whisper.cpp старше. Линковать обе статикой в один
бинарь нельзя по трём причинам. Первая: одинаковые имена `ggml_*` в двух архивах, и ld молча возьмёт
одну реализацию на символ, так что llama получит структуры и функции чужой версии (неопределённое
поведение, падения в Metal-бэкенде). Вторая: `llama.h` включает свой `ggml.h`, а bridging-заголовок
уже импортирует `ggml.h` whisper, то есть два разных определения одних типов в одном модуле Clang.
Третья: любая будущая правка whisper ломала бы llama и наоборот.

Решение: отдельная самодостаточная библиотека `libkeyboop_llm.dylib`.

1. llama.cpp пиннится на тег `b11600` (commit `ace20f679e30a39c09a7b17bec14199855469633`, 13.10.2026,
   архитектура `gemma4` в нём есть) и собирается статикой (`BUILD_SHARED_LIBS=OFF`).
2. Маленький C-шим `Native/llm/kb_llm.c` с четырьмя функциями на простых C-типах линкуется с этой
   статикой в один dylib. Наружу экспортируются только `kb_llm_*` (`-exported_symbols_list`), все
   `ggml_*` и `llama_*` внутри скрыты, поэтому с ggml из whisper они не пересекаются ни при линковке,
   ни при загрузке (двухуровневое пространство имён macOS плюс скрытые символы).
3. Swift загружает dylib через `dlopen(RTLD_LOCAL)` и берёт четыре функции `dlsym`, как GigaAM
   берёт ONNX Runtime. `llama.h` в Swift не импортируется вовсе, bridging-заголовок не меняется.
4. Metal-шейдеры встраиваются в библиотеку (`GGML_METAL_EMBED_LIBRARY=ON`), чтобы два экземпляра
   ggml-metal не спорили за `default.metallib`. Каждый создаёт своё устройство и очереди, это штатно.
5. Таргет arm64 `macOS 14.0`, как у whisper (иначе сильная ссылка на `MTLResidencySetDescriptor` и
   падение на Sonoma). Срез x86_64 (`KEYBOOP_UNIVERSAL=1`) собирается без Metal, с AVX2, таргет 13.0.

Если llama.cpp не собран, `build-app.sh` пишет подсказку и собирает приложение без dylib. Функция
тогда честно показывает «движок не входит в эту сборку». Существующая сборка ничего не теряет.

Intel. Swift-код один для обеих архитектур; `#if arch(arm64)` выбирает выгрузку слоёв в Metal, на
x86_64 всё на CPU. Скорость на Intel не проверена и может быть неприемлемой, это надо мерить.

## Контекст для модели (всё локально)

1. Текст до каретки в фокусном поле через Accessibility (`kAXStringForRange`, как `AXScreenCheck`,
   таймаут 50 мс), до 1500 символов, в промпт идут последние 1200. Чтение идёт с фоновой очереди,
   не с main, где живёт event tap.
2. Последняя диктовка из `VoiceHistory.shared.lastVisible()`, то есть только если история включена
   и запись не просрочена по сроку хранения. Тумблер «Учитывать диктовку».
3. Текст с экрана, отдельный тумблер, нужен доступ «Запись экрана». Снимок только переднего окна
   переднего приложения (`SCScreenshotManager`, macOS 14+), без окон Keyboop, сразу в
   `VNRecognizeTextRequest` на устройстве, после чего `CGImage` отпускается. Картинка никогда не
   кодируется, не пишется на диск и никуда не отправляется. Хранится только распознанный текст, не
   больше 1500 символов, в памяти, не дольше 60 секунд, и сбрасывается при смене приложения.
   Снимок делается не чаще раза в 20 секунд и только когда человек печатает.

Честная оговорка для настроек: macOS 15+ сама периодически переспрашивает разрешение на запись
экрана, и в строке меню появляется индикатор захвата экрана. Это поведение системы, обойти его нельзя
и не нужно.

## Когда подсказки нет

Функция выключена; модель не скачана или dylib нет; пауза Keyboop; идёт диктовка; поднят Secure
Input; под кареткой поле пароля или поле не читается (`SecureInputPolicy.focusedFieldVerdict`
не `.ordinary`); есть выделение; переднее приложение в списке исключений подсказок или для него в
`ExceptionStore` стоит режим «выкл»; переднее приложение это сам Keyboop; текст до каретки короче
трёх символов. Снимок экрана дополнительно не делается при любом из этих условий.

По умолчанию в исключениях менеджеры паролей: 1Password, Bitwarden, «Связка ключей», «Пароли».

## Генерация

Пауза 300 мс после последней клавиши, затем один запрос. Любая клавиша отменяет текущую генерацию
(флаг отмены проверяется шимом на каждом токене) и прячет подсказку. Жадная выборка, до 16 токенов,
остановка на переводе строки и конце предложения. Промпт собирается по шаблону Gemma 4
(`<|turn>system`, `<|turn>user`, `<|turn>model`), без режима размышлений; ответ модели
предзаполняется хвостом текущей фразы, чтобы модель продолжала её, а не пересказывала. Ответ чистится
(служебные токены, повтор уже набранного, пробел на стыке).

## Показ и принятие

Призрачный текст рисуется в `NSPanel` без активации и без мыши, справа от прямоугольника каретки
(`CaretLocator`), шрифт по высоте каретки. Там, где AX не отдаёт каретку (часть Electron и веба),
подсказка не показывается вовсе: угадывать место хуже, чем промолчать. Это не настоящий текст в поле,
а наложение, поэтому при прокрутке без нажатий оно может разойтись с полем; оно прячется по клику,
смене приложения и через 8 секунд.

Клавиша принятия (Tab по умолчанию, вариант «→») перехватывается в `EventTap` ТОЛЬКО пока подсказка
на экране. Тогда нажатие глотается (с парным keyUp), а текст печатается `TextReplacer.insert`: Unicode-
синтетика, буфер обмена не участвует. После вставки шлётся `keyboopVoiceInserted`, и `Engine` чистит
буфер набора так же, как после диктовки. Раскладка не переключается. Во всех остальных случаях Tab
проходит в приложение как раньше.

## Правки существующего кода

Новые файлы: `PredictionModel.swift`, `LLMRuntime.swift`, `PredictionPrompt.swift`,
`ScreenContext.swift`, `GhostTextOverlay.swift`, `InlinePredictor.swift`,
`PredictionSettingsView.swift`, `Native/llm/*`. Существующие правки: одна ветка в `EventTap`
(keyDown), раздел в `SettingsSection` и одна строка в `buildSection`, функция открытия панели
записи экрана в `Permissions`, строки в `L10n` отдельным словарём в конце файла, необязательный
блок в `build-app.sh`, `NSScreenCaptureUsageDescription` в Info.plist.

## Что проверено без Mac и что проверить на Mac

Проверено в облаке (Linux): URL, размер, SHA-256 и заголовок GGUF модели; шим собран и прогнан
против llama.cpp `b11600` на CPU; синтаксис Swift-файлов (`swiftc -parse`); логика `PredictionPrompt`
тестом; логика `build-app.sh` через `bash -n`.

Проверить на Mac: сборка arm64 и universal; `nm -gU libkeyboop_llm.dylib` показывает только
`kb_llm_*`; диктовка whisper работает с загруженной моделью подсказок в том же процессе; задержка
первого токена и память (оценка 3,5 ГБ, не измерено); выдача доступа «Запись экрана» и честный
отказ без него; поля паролей (Safari, системный диалог) не дают ни подсказки, ни снимка; Tab в
Terminal, Xcode, браузере без подсказки работает как раньше; положение призрака в TextEdit, Notes,
Safari, Mail, Telegram; поведение на Intel.
